## 1. Коротко

Anonymizer готовит документы к отправке во внешнюю нейросеть. Он находит персональные данные, банковскую и
коммерческую тайну и заменяет их метками: `[FIO_1]`, `ООО «[YUL_2]»`, `[INN_3]`. Потом в ответ нейросети программа
возвращает исходные значения, ФИО - в нужном падеже. Всё работает на компьютере, внешних служб нет.

Пользователь - юрист банка или компании (`docs/Продукт.md`). Главная метрика - **полнота**: пропущенное имя уходит за
рубеж, лишняя маска лишь немного мешает.

Главные сценарии:
1. **Обезличить и отправить:** «Обезличить» → перетащить файлы → «Обезличить» → «Просмотр» (проверить, поправить) →
   «Скачать» → «Скопировать инструкцию для нейросети».
2. **Вернуть данные:** «Вернуть данные» → выбрать сессию → загрузить ответ нейросети → «Вернуть данные» → «Просмотр»
   (зелёным - точно, жёлтым - падеж подобран, красным - метка не найдена) → «Скачать».
3. **Поправить найденное:** «Просмотр» → «Не маскировать» / «Замаскировать» выделенное / «Изменить» → файл
   пересобирается сам. «Всегда» и «никогда» - в «Словаре».

**Слова окна** (одно понятие - одно слово):

| Слово | Что значит | Вместо прежних |
|---|---|---|
| метка | `[FIO_1]` в обезличенном тексте | токен, плейсхолдер |
| запись | значение и его метка - строка таблицы замен | маппинг, сущность |
| таблица замен | все записи сессии | маппинг сессии, таблица соответствий |
| сессия | файлы, обезличенные вместе, и их таблица замен | - |
| вид | ФИО, организация, ИНН… (31 вид, 5.3) | тип, тип сущности |
| «Обезличить» / «Вернуть данные» | два раздела работы | анонимизация, деанонимизация, восстановление |
| «Не маскировать» | снять маску с записи | удалить, удалить из замен, 🗑️ |
| модель распознавания имён | находит ФИО и организации | spaCy, NER |
| нейросеть | необязательная локальная проверка | LLM, Ollama, Qwen |

### 3.2 Обезличить

- **Назначение:** загрузить файлы, обезличить, проверить, скачать.
- **Как попасть:** меню «Обезличить»; строка сессии в «Сессиях» (открывает эту сессию здесь).
- **Что видно сверху вниз** (макеты `1-3`):
  1. Заголовок «Обезличить», строка «Файлы одной сессии получают общие метки: один человек - одна метка во всех
     файлах.»; справа - главная кнопка **«Обезличить (N)»**.
  2. Строка сессии: «Сессия 24.10 · 3 файла · 41 запись», ✏️ «Переименовать», «Новая сессия». Сессии ещё нет -
     «Сессия появится сама при первом файле».
  3. Зона загрузки: «Перетащите файлы или выберите на компьютере», «Word, PDF, сканы, Excel, PowerPoint, RTF, TXT,
     фото». Когда файлы уже есть - узкая полоса той же зоны.
  4. Блок хода работы (фиксированной высоты, ничего не прыгает) - во время обработки; блок итога - после.
  5. Список файлов сессии - строками.
  6. «Таблица замен» (3.3).

| Элемент | Что делает | Что меняется на экране / в данных | Когда неактивен и почему |
|---|---|---|---|
| «Обезличить (N)» | обезличивает новые файлы | блок хода работы, строки файлов | нет новых файлов - неактивна, подпись под ней «Добавьте файлы» |
| зона загрузки | выбор или перетаскивание; каждый файл уходит своим запросом | строка «Новый · 1,2 МБ»; тот же файл второй раз не добавляется («Этот файл уже в сессии»); чужой формат - строкой «Формат не поддерживается» | идёт обработка - файлы встают в очередь сессии |
| ✏️ «Переименовать» | поле с именем сессии на месте, Enter - сохранить, Esc - отмена | имя в пути и в «Сессиях» | - |
| «Новая сессия» | закрывает текущую, «Обезличить» пустой; сессия создастся при первом файле | путь в шапке | нет сессии - кнопки нет |
| «Остановить» (в блоке хода) | прерывает обработку после текущего файла (≤ 3 с, если идёт нейросеть) | «Остановлено: готово 2 из 3. «Обезличить» продолжит с третьего» | - |
| «Просмотр» в строке | Просмотр (3.6) | - | PowerPoint - вместо кнопки «Просмотра для презентаций нет - скачайте файл» |
| «Скачать ▾» в строке | Word (или исходный формат), PDF - если в Настройках «Также сохранить PDF» | файл в «Загрузки» | файл не готов |
| «⋯» в строке | «Убрать из сессии» (окно: «Файл и его оригинал удалятся. Записи таблицы замен останутся - они нужны другим файлам и для «Вернуть данные».»); «Проверить ещё нейросетью» - только если нейросеть включена | файл и оригинал удалены сразу | - |
| «Скачать все (ZIP)» (в итоге) | обезличенные файлы сессии одним архивом - только этого раздела | архив в «Загрузки» | готовых файлов меньше двух - кнопки нет |
| «Скопировать инструкцию для нейросети» (в итоге) | копирует текст для внешней нейросети: метки не изменять, не склонять, не переводить, не объединять; одна метка - одно лицо или одна организация | строка «Скопировано - вставьте перед документом в чат нейросети»; буфер недоступен - окно программы с выделенным текстом и «Закрыть» | - |

- **Ход обработки** (блок хода, стандарт 2.2): полоса с процентом; «Файл 2 из 3 · Ищу данные · 0:14 · осталось
  ~0:20»; «Остановить». Этапы: «Читаю файл» → «Ищу данные» → «Заменяю» → «Проверяю утечки» (и «Проверяю
  нейросетью» - в фоне после готового файла, если она включена). Строки файлов: «В очереди» → этап → итог.
- **Модель распознавания имён ещё загружается** (было Р-13): «Обезличить» нажимается. В блоке хода - «Готовлю
  распознавание имён… обработка начнётся сама». Без модели обработка не идёт: ФИО и организации нашлись бы только
  правилами.
- **Модель не загрузилась:** в блоке - «Модель распознавания имён не загрузилась» и две кнопки. «Повторить» -
  `/api/ner-retry`. «Обезличить без распознавания имён» - красным, с подписью «ФИО и организации найдутся только
  правилами - проверьте каждый файл в «Просмотре» перед отправкой».
- **Итог** (макет `3`): «Готово: 3 файла · 41 запись · утечек нет» (или «Проверьте 2 файла» жёлтым) · «Скачать все
  (ZIP)» · «Скопировать инструкцию для нейросети».
- **Имена файлов** (было Р-39, правка 6 дизайн-чата): в окне - исходное имя («Договор поставки - Петров.docx»), под
  ним - имя обезличенного файла; скачиваемые файлы и ZIP - **только с метками** («Договор поставки [FIO_1].docx»,
  архив «Обезличенные файлы - 24.10.zip», файлы «Вернуть данные» - «Данные возвращены - 24.10.zip»: в имени архива только дата сессии). Имя исходного файла не уходит ни в файл, ни в архив, ни в журнал.
- **Строка файла:**
  - готово: «Найдено 14 · утечек нет · Договор поставки [YUL_1].docx»;
  - проверьте: «Найдено 9 · проверьте 2 места - откройте «Просмотр»: там их можно замаскировать» (жёлтым; список мест
    - в «Просмотре», 3.6);
  - не заменилось: «3 значения не удалось заменить в файле - не отправляйте его» (красным), «⋯ → Открыть журнал»;
  - фото и сканы: «Закрашено по распознанному тексту - вернуть данные в этот файл нельзя»;
  - нейросеть (если включена): «Нейросеть проверяет найденное…» → «Нейросеть: замечаний нет» или «Нейросеть
    предлагает: найти ещё 2, снять 1 - Посмотреть» (3.15);
  - ошибка - по-русски, с действием (4.6).
- **Данные:**
  - оригиналы - `uploads/<сессия>/input/`, ответы нейросети для «Вернуть данные» - `uploads/<сессия>/replies/`,
    готовые файлы - `uploads/<сессия>/output/`;
  - список файлов сессии - `uploads/<сессия>/manifest.json`: раздел («обезличить» / «вернуть»), вход → выход, итог
    (число записей, проверка утечек, итог нейросети);
  - найденное - `anon.db` (`mappings`, `places`, `occurrences`).
- **Повторное открытие сессии** (было Р-17, Р-18): файлы - по разделу из `manifest.json`, не по имени. Итоги -
  те же, что сразу после обработки: найдено, проверка утечек, итог нейросети. Файлы «Вернуть данные» - только там.
- **Состояния:**
  - пусто: зона загрузки и «Сессия появится сама при первом файле» - макет `0`;
  - файлы выбраны - макет `1`;
  - обработка, модель загружается - макет `2`;
  - остановлено; готово - макет `3`; частично: «Готово 2 из 3», красная строка у файла;
  - модель не загрузилась (выше); ошибка (4.6);
  - нейросеть включена: видеокарта занята - окно 3.14, нет модели - «Нейросеть недоступна - файл после правил
    готов».
- **Ограничения:**
  - один файл - до 100 МБ, файлов в сессии - сколько угодно (каждый своим запросом);
  - форматы: `.txt .docx .docm .doc .odt .pptx .pdf .xlsx .xlsm .rtf .jpg .jpeg .png .heic .tif .tiff`;
  - DOC и ODT - через `textutil` (macOS) или LibreOffice; сканы и фото - Apple Vision (только macOS), они необратимы.
- **Сценарии проверки:**
  - UC-A1: вымышленный DOCX («Петров Иван Сергеевич», ИНН с верной контрольной суммой) → «Обезличить» → «Готово:
    1 файл · утечек нет», имя файла без фамилии; сессия «Сессия <дата>» появилась в «Сессиях».
  - UC-A2: 3 файла → «Обезличить» → полоса с процентом и этапом → «Остановить» → «Остановлено: готово N из 3» →
    «Обезличить» → обработан только остаток.
  - UC-A3: запуск, модель распознавания имён ещё грузится → «Обезличить» → «Готовлю распознавание имён…» → обработка
    началась сама; в файле ФИО найдены.
  - UC-A4: модель не загрузилась (подмена) → «Повторить» и красная «Обезличить без распознавания имён» с
    предупреждением.
  - UC-A5: обработать, вернуть данные, перезапустить программу, открыть сессию → обезличенные файлы - в
    «Обезличить» с прежними итогами, файлы с данными - только в «Вернуть данные».
  - UC-A6: файл 120 МБ → строка «Файл больше 100 МБ - разделите его», остальные файлы обработаны.
  - UC-A7: «Убрать из сессии» → окно программы → файла нет в списке и на диске, записи таблицы замен на месте.
  - UC-A8: «Скопировать инструкцию для нейросети» → в буфере текст инструкции.

### 3.3 Таблица замен

- **Назначение:** все записи сессии в одной таблице: найти, исправить, добавить, снять маску и вернуть её.
- **Где:** под списком файлов в «Обезличить»; заголовок «Таблица замен · 41» сворачивает и разворачивает.
- **Что видно** (макет `3`): поиск «Найти: фамилия, ИНН, метка…»; фильтр «Вид: все ▾» - все 31 вид (5.3) и
  отдельным пунктом **«Не маскируется»**; «+ Добавить вручную»; таблица «Метка | В документе | Начальная форма | Вид
  | ⋯»; у заголовка «Начальная форма» - подсказка «ФИО - в именительном падеже, программа склонит сама». Одна строка -
  одна метка, все формы через « · » (первая - основная).

| Элемент | Что делает | Что меняется | Когда неактивен |
|---|---|---|---|
| поиск | по метке, формам, начальной форме | строки; пусто - «Ничего не найдено» | - |
| «Вид ▾» | 31 вид + «Не маскируется» | строки | - |
| «+ Добавить вручную» | окно записи (3.4) | новая запись; файлы сессии пересобраны | **доступна всегда** (было Р-20). До первого файла - подпись в окне «Добавится и применится при обработке» |
| «⋯» строки → «Изменить» | окно записи | новая метка (старая остаётся для прежних файлов) или та же, если менялась только начальная форма; пересборка | - |
| «⋯» строки → «Не маскировать» | 3.5 | строка уходит в «Не маскируется»; пересборка | - |
| «⋯» строки в «Не маскируется» → «Вернуть маску» | маска снова действует, метка та же (было Р-22) | строка возвращается в таблицу; пересборка | - |

- **Пересборка:** после любой правки файлы сессии пересобираются сами. В строках файлов - «Пересобираю…», в итоге -
  новые числа. Кнопки «Переобработать» нет и не нужно (было Р-19).
- **Данные:** `mappings` (`status`: active / excluded = «не маскируется» / replaced = изменена). Записи не удаляются,
  номера меток не переиспользуются - иначе не вернутся данные в прежние ответы нейросети.
- **Состояния:**
  - пусто: «Записей пока нет - они появятся после обработки. Можно добавить вручную»;
  - ничего не найдено;
  - фильтр «Не маскируется» пуст: «Все записи маскируются».
- **Сценарии проверки:**
  - UC-M1: «+ Добавить вручную» значение, которое уже есть другой формой → «Такое значение уже есть: [ADR_1] …» →
    «Объединить с ним» / «Всё равно добавить отдельно» / «Отмена».
  - UC-M2: «+ Добавить вручную» до первого файла → запись в таблице; после обработки значение в файле - меткой.
  - UC-M3: «Не маскировать» → фильтр «Не маскируется» → «Вернуть маску» → в файле снова метка, та же.
  - UC-M4: фильтр «Вид ▾» - 31 вид, каждый находит свои строки.

### 3.4 Окно записи: «Добавить запись» / «Изменить запись» / «Замаскировать»

- **Как попасть:** «+ Добавить вручную»; «⋯ → Изменить» в таблице; «Изменить» в просмотре; «Замаскировать» после
  выделения текста в просмотре.
- **Что видно:**
  - заголовок; «Метка: [FIO_1]» (только при правке);
  - «Значение в документе» - «Ровно как в документе: это значение ищется и заменяется меткой»;
  - «Начальная форма (необязательно)» - «ФИО - в именительном падеже, программа склонит сама. Она вставляется в новый
    текст ответа нейросети»;
  - «Вид» - 31 вид, при «Замаскировать» угадан по тексту;
  - **«Маскировать: только в этой сессии / всегда»** - по умолчанию «только в этой сессии»; «всегда» кладёт значение
    в «Словарь → Всегда маскировать» (3.11). При правке переключатель показан, только если значение уже в Словаре;
  - «Отмена» / «Сохранить».
- **Действия:**
  - «Сохранить» и Enter (в однострочном поле) - сохранить, пересобрать файлы;
  - значение уже принадлежит другой метке - окно «Такое значение уже есть»;
  - оба поля пустые - «Заполните значение».
  - Esc, щелчок мимо и «Отмена» закрывают окно без изменений (было Р-27).
- **Данные:** новое значение снимается со списка «не маскируется» этой сессии. **В Словарь - только при «всегда»**
  (было Р-24: туда молча шло всё).

### 3.5 «Не маскировать» - одно действие одним словом

Было Р-21: одно действие называлось трижды - 🗑️, «Не маскировать», «Удалить из замен» - с разными
подтверждениями.

- **Где:** «⋯ → Не маскировать» в таблице замен; «Не маскировать» во всплывающем окне метки и в правой панели
  просмотра.
- **Окно** (макет `5`): «Не маскировать «Петров Иван Сергеевич»? В файлах значение останется открытым.» Ниже переключатель:
  «только в этой сессии» (по умолчанию) / «всегда - в Словарь «Никогда не маскировать»». Кнопки «Не маскировать»
  (главная, Enter) и «Отмена» (Esc, щелчок мимо).
- **После:** запись уходит в «Не маскируется», файлы пересобираются, внизу 5 с строка «Петров Иван Сергеевич больше не
  маскируется · Вернуть». «Вернуть» отменяет и пересобирает файлы.
- **Сценарий:** UC-U1: в просмотре «Не маскировать» у метки → окно → «Не маскировать» → в тексте значение открыто,
  строка «Вернуть» → «Вернуть» → снова метка; с «всегда» - значение в «Словаре → Никогда не маскировать», в новой
  сессии не маскируется.

### 3.6 Просмотр обезличенного файла

- **Назначение:** увидеть результат, не открывая файл; проверить и поправить на месте.
- **Как попасть / уйти:** «Просмотр» в строке файла - экран внутри «Обезличить», путь «Обезличить › Сессия 24.10 ›
  Договор поставки - Петров.docx» (исходное имя); «← Назад» - к списку файлов. Не окно поверх: «Назад» и путь, как везде.
- **Что видно** (макет `4`):
  1. Строка над документом: «Скачается как: Договор поставки [YUL_1].docx» (имя с метками); поиск «Найти в тексте: слово, фамилия, метка…»; «☐ Показать исходный
     текст»; «Скачать ▾».
  2. Документ на белом листе (в обеих темах, 1.9):
     - Word - как в Word (docx-preview);
     - Excel - по листам; показано не всё - пометка «Показаны первые 800 строк и 40 столбцов листа - весь лист в
       скачанном файле» (было Р-42);
     - PDF-сканы - страницами, фото - картинкой, TXT - текстом;
     - метки - цветные «чипы» по группе вида: ФИО, организации, адреса, реквизиты и номера.
  3. Правая панель 360 px:
     - «Проверьте: 2 места» (жёлтым, если проверка утечек нашла подозрительное) - щелчок к месту;
     - «Проверка дублей · N» (если есть);
     - фильтр «Найти: фамилия, ИНН…» и «Вид ▾»;
     - группы значений: значение, «×N», метка мелко; выбранное - с кнопками «Изменить», «Другое написание…», «Не
       маскировать».

| Элемент | Что делает | Что меняется | Когда неактивен |
|---|---|---|---|
| значение в панели | к месту в тексте; ещё щелчок, ↑ / ↓ - следующее вхождение | метка мигает; под значением - кнопки | значение только на картинке страницы - «Есть только на изображении страницы» |
| «Изменить» | окно записи (3.4) | пересборка, просмотр обновлён на том же месте | - |
| «Другое написание…» | окно «Другое написание для [FIO_1]»: поле, «только в этой сессии / всегда», «Добавить» | та же метка для другого написания | - |
| «Не маскировать» | 3.5 | пересборка | - |
| метка в тексте | всплывающее окно: метка, вид, все формы; «Не маскировать», «Изменить», «Объединить с… ▾» | пересборка | «Объединить с…» - если есть другие метки этого вида |
| выделить текст (2-300 знаков, без меток) | кнопка «Замаскировать» под выделением → окно записи с готовым значением | «Замаскировано: [FIO_4]»; пересборка | - |
| «Проверка дублей» | пары «похоже на одно и то же»: «Объединить» · «Это разные» (больше не предлагается) | `merge`, `distinct` | - |
| «Показать исходный текст» | вместо меток - значения, стоявшие в этом месте | только показ | сканы и фото |

- **Данные:** `GET /api/sessions/<id>/preview/<файл>`: текст до 300 000 знаков, формы меток, места, проверка утечек,
  пары дублей.
- **Состояния:**
  - «Открываю документ…»;
  - Word не нарисовался - показан текстом, строка «Показан текст файла: вёрстку Word нарисовать не удалось»;
  - «В файле нет текста»;
  - ошибка - «Просмотр не открылся: <что случилось>. Скачайте файл и откройте его в Word».
- **Сценарии проверки:**
  - UC-P1: «Просмотр» → документ с чипами, справа группы с числами; щелчок по значению → к месту, ↓ → следующее;
    «← Назад» → список файлов на месте.
  - UC-P2: выделить фамилию → «Замаскировать» → «Сохранить» → на месте фамилии метка.
  - UC-P3: две похожие организации → «Проверка дублей» → «Это разные» → пара больше не предлагается.
  - UC-P4: Excel 1 000 строк → пометка «Показаны первые 800 строк…».

### 3.7 Вернуть данные

- **Назначение:** вернуть исходные значения в ответ внешней нейросети (или в свой обезличенный файл).
- **Как попасть:** меню «Вернуть данные»; «⋯ → Вернуть данные» у сессии в «Сессиях».
- **Что видно** (макет `6`):
  - заголовок «Вернуть данные», строка «Загрузите ответ нейросети - метки заменятся значениями из выбранной
    сессии.», справа главная **«Вернуть данные (N)»**;
  - «Сессия: [Сессия 24.10 · 3 файла ▾]» - по умолчанию выбранная, иначе последняя;
  - зона загрузки, список файлов этого раздела, блок хода и итог, как в 3.2;
  - легенда цветов просмотра: «точно · падеж подобран · не найдено».

| Элемент | Что делает | Что меняется | Когда неактивен |
|---|---|---|---|
| «Сессия ▾» | выбор сессии, чьи записи подставлять | путь в шапке | сессий нет - «Сначала обезличьте файлы: данные возвращаются из той сессии, где их заменили» |
| «Вернуть данные (N)» | метки → значения | строки файлов, итог | нет новых файлов |
| «Просмотр» | 3.8 | - | фото и сканы |
| «Скачать ▾», «⋯ → Убрать из сессии» | как в 3.2 | - | - |
| «Скачать все (ZIP)» | файлы с возвращёнными данными - только этого раздела (было Р-40) | - | готовых меньше двух |

- **Как работает:**
  - метки ищутся с допуском: `FIO_1`, `[FIO 1]`, `[fio-1]`, `[ФИО_1]`;
  - неизменённый абзац или ячейка получают ровно те формы, что были в этом месте;
  - в новом тексте ФИО склоняется по правилам (`core/cases.py`);
  - неясный падеж - нейросетью, только если она включена (вопрос 2), иначе правилом с жёлтой подсветкой;
  - организация без кавычек и ОПФ получает их по Настройкам.
- **Вставить текст** (вопрос 1 - да; основной путь: ответ нейросети чаще текст в чате): под зоной загрузки -
  переключатель «Файл | Текст». «Текст» - поле «Вставьте ответ нейросети» (Cmd+V), кнопка «Вернуть данные»; под полем -
  результат с подсветкой (те же цвета, что в просмотре 3.8), итог «Вернулось 12: 10 точно, 2 с подбором падежа» и
  «Скопировать» (обычным текстом). Текст не сохраняется на диск и пропадает при уходе с экрана.
- **Имя файла с возвращёнными данными** (правка 1): «<имя ответа с данными> (данные возвращены).docx», например
  «Претензия покупателю (данные возвращены).docx»; не `_restored`.
- **Строка файла:**
  - «Вернулось 37: 31 точно, 6 с подбором падежа»;
  - «Не найдены в этой сессии: [FIO_9] - проверьте, та ли сессия выбрана» (красным);
  - фото и скан - «Изображение вернуть нельзя: закрашенное необратимо».
- **Нейросеть включена и видеокарта занята** (было Р-11): окно 3.14 до начала - без молчаливого ожидания 60 с.
  «Отмена» - падеж только правилами.
- **Данные:** что и как вставлено - `uploads/<сессия>/restore_marks/<файл>.json`; раздел «вернуть» - в
  `manifest.json`.
- **Сценарии проверки:**
  - UC-D1: изменить «Начальную форму» у ФИО → вернуть ответ с меткой в новом предложении → в файле
    исправленная форма в нужном падеже.
  - UC-D2: ответ с меткой не из этой сессии → «Не найдены в этой сессии: …».
  - UC-D3: две сессии → «Сессия ▾» → вторая → значения из второй.
  - UC-D4: «Текст» → вставить ответ с [FIO_1] в новом предложении → «Вернуть данные» → значение в нужном падеже
    подсвечено жёлтым, «Скопировать» → в буфере текст без меток.
  - UC-D5: имя файла с возвращёнными данными - «… (данные возвращены).docx».

### 3.8 Просмотр файла с возвращёнными данными

- **Как попасть:** «Просмотр» в строке файла «Вернуть данные»; путь «Вернуть данные › Сессия 24.10 › <файл>».
- **Что видно:** итог «Вернулось 37: 31 точно, 6 с подбором падежа, 0 не найдено»; в тексте вставленные значения
  подсвечены: зелёным - точно, жёлтым - падеж подобран, красным - метка не найдена (токены `--ok-soft`,
  `--warn-soft`, `--bad-soft`); справа - легенда и список «Вставлено · 37»: сначала не найденные, потом с падежом,
  потом точные; щелчок - к месту.
- **Нет:** «Замаскировать», правки записей, проверки утечек - значения в файле здесь и должны быть.
- **Сценарий:** UC-R1: вернуть ответ с меткой в новом тексте → жёлтая подсветка и итог над документом.

### 3.9 Сессии

- **Назначение:** все сессии: открыть, переименовать, вернуть данные, удалить.
- **Что видно** (макет `8`): заголовок «Сессии», строка «Сессия хранит файлы и таблицу замен. Удаляется целиком через
  30 дней (Настройки → Хранение).»; главная **«+ Новая сессия»**; поиск «Найти сессию»; список строками, последние
  сверху (стандарт 3.1):
  - галочка;
  - имя («Сессия 24.10»);
  - строка «3 файла · 41 запись · 24.10.2026, 14:05»;
  - пометка «удалится через 3 дня» (жёлтым, за 3 дня до срока);
  - «⋯», ✕ «Удалить» (всегда видна, было Р-15).
- **Число записей** - одно понятие во всей программе (было Р-16): активные записи таблицы замен, то же число, что в
  заголовке «Таблица замен · 41».

| Элемент | Что делает | Что меняется | Когда неактивен |
|---|---|---|---|
| строка | открывает сессию в «Обезличить» | путь | - |
| «+ Новая сессия» | «Обезличить» пустой, сессия создастся при первом файле | - | - |
| поиск | по имени сессии | строки | - |
| «⋯» → «Открыть» / «Переименовать» / «Вернуть данные» / «Скачать все (ZIP)» / «Удалить» | как названо; «Переименовать» - поле на месте | - | «Скачать все» - если готовых файлов больше одного |
| ✕ | окно удаления (3.10) | - | - |
| галочки → «Удалить выбранные (N)» | окно удаления для N сессий | - | ничего не отмечено - кнопки нет |

- **Имя сессии** (было Р-39): «Сессия 24.10»; вторая за день - «Сессия 24.10 (2)». Имя файла в имя сессии не идёт.
  Переименовать - вручную. В пути шапки и в строке сессии рядом с именем - число файлов.
- **Срок хранения** (было Р-38): при запуске и раз в сутки удаляются сессии, которые старше срока из Настроек.
  Удаляется сессия целиком: записи, места, исключения, папка файлов.
- **Данные:** `anon.db` - `sessions`, `mappings`; `uploads/<сессия>/`.
- **Состояния:**
  - пусто: «Сессий нет. Начните с «Обезличить» - сессия появится сама.»;
  - поиск без результата: «Ничего не найдено».
- **Сценарии проверки:**
  - UC-S1: обработать файл → в «Сессиях» «Сессия <дата>» с «1 файл · N записей»; имя без имени файла.
  - UC-S2: «⋯ → Переименовать» → новое имя в списке и в пути.
  - UC-S3: сессия старше 27 дней (подмена даты) → «удалится через 3 дня»; старше 30 → её нет, папки нет, записей в
    базе нет.
  - UC-S4: поиск по части имени.

### 3.10 Окно удаления сессии

- **Как попасть:** ✕ или «⋯ → Удалить» у сессии; «Удалить выбранные (N)».
- **Окно** (макет `9`):
  - заголовок «Удалить «Сессия 24.10»?»;
  - текст «Удалятся оригиналы, обезличенные файлы и таблица замен (3 файла, 41 запись). Вернуть данные в ответ
    нейросети после этого будет нельзя. Отменить удаление нельзя.»;
  - кнопки «Удалить навсегда» (красная) и «Отмена»;
  - фокус - на «Отмене», Enter не удаляет. Esc и щелчок мимо закрывают.
  - Для N сессий - «Удалить 2 сессии?» и общие числа.
- **После:** сессии нет в списке, папки нет, записей в базе нет. Строка «Сессия удалена». «Вернуть» нет -
  исключение из стандарта 3.2 для персональных данных (152-ФЗ, ст. 5 ч. 7).
- **Словарь** удаление не трогает: в окне строка «Словарь (3.11) остаётся - он общий для всех сессий».
- **Сценарий:** UC-S5: ✕ → окно с числами → Esc → сессия на месте; ✕ → «Удалить навсегда» → нет в списке, нет
  `uploads/<id>`, `SELECT count(*) FROM mappings WHERE session_id = …` = 0.

### 3.11 Словарь

- **Назначение:** значения, которые программа маскирует или не маскирует во всех сессиях. Видно, откуда они
  взялись, их можно удалить (было Р-24).
- **Что видно** (макет `7`):
  - заголовок «Словарь», строка «Действует во всех сессиях. Хранится отдельно от сессий: удаление сессии его не
    трогает.»;
  - главная **«+ Добавить»**;
  - переключатель «Всегда маскировать · 12» | «Никогда не маскировать · 5»;
  - поиск;
  - строки: значение, вид, откуда («добавлено 24.10 вручную», «из «Не маскировать»», «20.10, до версии 4.0»), ✕;
  - внизу ссылка «Очистить список…»;
  - **после перехода на 4.0** - одна строка над списком «Всегда маскировать»: «Перенесено N значений из прежней памяти -
    проверьте список» и ✕ (строка скрывается навсегда).

| Элемент | Что делает | Что меняется | Когда неактивен |
|---|---|---|---|
| «+ Добавить» | окно: значение, вид, список (всегда / никогда) | строка в списке; действует с следующей обработки | - |
| ✕ у строки | убирает из Словаря сразу; строка 5 с «Убрано · Вернуть» | в новых сессиях значение снова ищется как обычно; готовые файлы не меняются | - |
| «Очистить список…» | окно «Убрать из Словаря все 12 значений? Готовые файлы не изменятся.» → «Очистить» | список пуст | список пуст |

- **Как действует:**
  - «Всегда маскировать» - первым проходом в каждой сессии (`_apply_global_known`);
  - «Никогда не маскировать» - исключение в каждой сессии (`db.ExclusionSet`).
  - Значение в обоих списках сразу быть не может: добавление в один убирает из другого (строка «Перенесено из
    «Никогда не маскировать»»).
- **Данные:** `known_entities` (всегда) и новая таблица `never_mask` (никогда) в `anon.db`. Миграция - 5.4: прежняя
  память переходит в «Всегда маскировать» с пометкой «до версии 4.0»; на экране - строка «Перенесено N значений из
  прежней памяти - проверьте список».
- **Срок:** Словарь хранит значения без срока, пока их не удалят (в Справке - «Что такое сессия и Словарь»).
- **Состояния:**
  - «Всегда маскировать» пуст: «Пусто. Сюда попадают значения, для которых вы выбрали «всегда» при добавлении
    вручную»;
  - «Никогда не маскировать» пуст: «…при «Не маскировать»».
- **Сценарии проверки:**
  - UC-W1: «+ Добавить вручную» с «всегда» → значение в «Всегда маскировать» → новая сессия, файл с этим значением
    → маска.
  - UC-W2: ✕ → «Вернуть» → строка на месте; ✕ → через 5 с её нет; новая сессия → значение не маскируется
    Словарём.
  - UC-W3: удалить сессию → Словарь не изменился.

  (было Р-28: «Сохранить» и неверный тост).
- **Что видно** (макет `10`; стандарт 4.1, 4.2 - группы по задачам, у параметра одна строка пояснения):

  - UC-N3: ни один выпадающий список не обрезает текст (4.4).

### 3.13 Справка

- **Что видно:** экран «Справка» - те же разделы, что в этом описании, своими словами: «Как обезличить», «Как вернуть
  данные», «Что такое сессия и Словарь», «Что делать, если программа что-то не нашла», «Как хранятся данные»,
  «Нейросеть и видеокарта». В «Что такое сессия и Словарь» - что сессия удаляется по сроку, а Словарь хранит
  значения без срока, пока их не удалят. «Как пользоваться.docx» и «How to use.docx» собираются из того же текста
  (`scripts/build_howto_docx.py`, стандарт 5.1; было Р-31).

### 3.14 Окно «Видеокарта занята» (общий модуль `common/lock`)

- **Когда:** только при включённой нейросети. Варианты: «Обезличить» с проверкой, «Проверить ещё нейросетью»,
  «Вернуть данные» со спорным падежом - а замок `.heavy-lock` у другой программы или есть очередь.
- **Окно:** общее для всех программ (стандарт 2.4):
  - «Видеокарта занята: «<программа>», с <время>, <что делает>»;
  - «Подождать очереди», «Запустить сейчас», «На процессоре (очень медленно)» с прогнозом, «Отмена»;
  - ссылка «Открыть страницу «Видеокарта»».
- **Ожидание** (было Р-9, Р-10):
  - файл после правил готов сразу;
  - в строке файла - «Нейросеть ждёт видеокарту: «Herald» - начнётся сама · Отменить ожидание»;
  - в шапке - жёлтая строка «в очереди»;
  - через 30 мин без очереди - «Видеокарта всё ещё занята - нейросеть не проверила файл. Файл после правил готов».
- **Сценарий:** UC-G1: включить нейросеть, замок у «Herald» (свой файл замка теста) → «Обезличить» → окно с 4
  кнопками → «Подождать очереди» → «ждёт видеокарту… Отменить ожидание» → «Отменить ожидание» → проверки нет, файл
  готов.

### 3.15 Окно «Предложения нейросети»

- **Когда:** нейросеть включена, проверила файл и нашла замечания - «Посмотреть» в строке файла.
- **Что видно:** «Отметьте, что применить. Нейросеть может ошибаться.»; группы с галочками: «Замаскировать
  (пропустили правила)» - **отмечено**; «Снять маску (не персональные данные)» с причиной - **не отмечено** (было
  Р-25); «Объединить (одно и то же)» - отмечено; «Отмена» / «Применить».
- **Действие:** «Применить» → отмеченное применено, файлы пересобраны, в строке файла «Предложения нейросети
  применены». Esc и щелчок мимо закрывают (было Р-27).

## 4. Сквозные правила

4.1. **Язык окна** - RU | EN, все строки из словарей `static/i18n/ru.json`, `en.json`. Язык документа и меток не
меняется. Инструкция для нейросети - на языке окна.

4.2. **Тема** - системная / светлая / тёмная, все цвета токенами (`--bg`, `--surface`, `--text`, `--accent`, `--ok`,
`--warn`, `--bad` - как в LKD `app.css`), без `#000` в правилах. Лист документа - белый в обеих темах. Чипы меток -
четыре группы токенами (`--k-person`, `--k-org`, `--k-addr`, `--k-num`), контраст ≥ 4,5 : 1.

4.3. **Размер текста** - 17 px = 100 %, «Aa» 80-200 %, один раз сбросить сохранённый масштаб (стандарт 1.5).

4.4. **Окна подтверждения** - только свои, не `confirm()` и `prompt()` браузера (было Р-27). Esc и щелчок мимо -
закрыть. Enter - главное действие, кроме необратимых (удаление: фокус на «Отмене»).

4.5. **Числа и тексты** - короткое тире « - », «КБ / МБ», запятая в дробях, пробел в тысячах (было Р-30). Без
внутренних слов (1, таблица «Слова окна»).

4.6. **Ошибки** - что случилось и что сделать, без «HTTP 413» и текста исключений (было Р-41):

| Что | Текст |
|---|---|
| файл больше 100 МБ | «Файл больше 100 МБ - разделите его» |
| формат не поддерживается | «Такой формат не обрабатывается: подойдут Word, PDF, Excel, PowerPoint, RTF, TXT, фото» |
| файл защищён паролем или повреждён | «Файл не открылся - снимите пароль или сохраните его заново в Word» |
| скан на Windows | «Сканы и фото распознаются только на Mac» |
| нет места на диске | «На диске нет места - освободите и повторите» |
| сервер не отвечает | «Программа не отвечает - перезапустите её» |
| другое | «Не получилось обработать файл. Подробности - в журнале (Настройки → Служебное)» |

4.7. **Видеокарта** - только при включённой нейросети, через `common/lock` (без своей логики). Работа из окна - владелец
«человек», прогрев при запуске - «фон», только при свободной видеокарте. Прогоны Claude Code - `HEAVY_LOCK_WHO=background`.

4.8. **Хранение** (стандарт 6.4):
- данные - `~/Library/Application Support/Anonymizer` (Windows - `%APPDATA%\Anonymizer`), **и из исходников тоже**
  (было Р-35); журнал программы - папка `~/Library/Logs/Anonymizer/`, журнал запуска `.app` - `~/Library/Logs/Anonymizer.log`;
- `ANONYMIZER_DATA_DIR` - своя папка (тесты, стандарт 6.10);
- в папке: `anon.db`, `uploads/<сессия>/input|replies|output|restore_marks|manifest.json`, `backup-before-4.0/` (копия при переходе), `settings.json`.

4.9. **Удаление:**
- сессия - сразу и навсегда, с окном 3.10;
- файл - «Убрать из сессии», сразу;
- запись таблицы замен - никогда: «не маскируется» или «изменена»;
- Словарь - ✕ с «Вернуть» 5 с.

4.10. **Безопасность:**
- сервер слушает только `127.0.0.1:8070`;
- чужой Host, чужой Origin и межсайтовые запросы отклоняются;
- путь в имени файла запрещён;
- журнал - без значений и имён файлов (кроме режима диагностики до перезапуска).

4.11. **Версия окна и сервера** - `/api/info` (`{"version": "4.0.0"}`); окно сверяет при запуске и после
переподключения (было Р-32).

## 5. Модели и данные

5.1. **Модели:**
- **модель распознавания имён** (spaCy `ru_core_news_lg`, около 500 МБ, в комплекте): загружается в фоне при запуске,
  обработка её ждёт (3.2);
- **pymorphy3** - морфология ФИО;
- **локальная нейросеть** (Ollama, по умолчанию `qwen3.5:9b`) - только при «Использовать нейросеть». Держится
  30 мин после запроса; «На процессоре» - выгружается сразу;
- **Apple Vision** - сканы и фото (macOS);
- **pdf2docx** - PDF с текстом → Word; **textutil / LibreOffice** - DOC, ODT;
- **docx-preview** - просмотр Word.

5.2. **Форматы** - как в версии 1 (таблица форматов там не менялась): DOCX / DOCM / DOC / ODT → DOCX; PPTX; XLSX /
XLSM; PDF с текстом → DOCX (+ PDF по настройке); PDF-скан → PDF с плашками; RTF; JPG / PNG / HEIC / TIFF - закраска,
без EXIF; TXT.

5.3. **Виды записей (31)** - одним списком для окна записи, фильтров таблицы и просмотра:
- ФИО, Организация, Адрес;

## 6. Чего нет и почему

- **Облака и внешних служб** - данные не уходят с компьютера.
- **Корзины для сессий** - минимизация данных (3.10); исключение записано в стандарт 3.2.
- **Режимов «Быстро / Точно / Только нейросеть»** - один режим; польза нейросети по замерам 3.4.0 около нуля.
- **Возврата данных в сканы и фото** - закрашенное необратимо.
- **Просмотра презентаций** - слайды в окне нечитаемы, только «Скачать».
- **Распознавания сканов на Windows** - Apple Vision есть только на macOS.
- **Новой Windows-сборки** - решение Андрея 24.10: Windows - только Herald, Scribe, «Понятный документ».
  `build_windows.bat` и `Anonymizer.spec` для Windows остаются как есть и не проверяются.
- **pdf.js и «Было / стало» в две колонки** (стандарт 8.3) - для обезличивания «было» - это персональные данные на
  экране рядом с результатом. Вместо этого - «Показать исходный текст» на месте.
