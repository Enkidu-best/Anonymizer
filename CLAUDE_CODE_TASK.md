## 0. Правила работы (обязательны)

### 0.1. Ты проверяешь себя сам
Владелец не должен находить одни и те же ошибки по кругу. Поэтому каждое изменение идёт по циклу:

1. **Сначала тест.** Перед исправлением ошибки или добавлением формата добавь кейс в `tests/bench/corpus.py` или в `tests/test_*.py`, запусти и убедись, что он **падает**.
2. **Потом код.** Исправь.
3. **Проверка.** Запусти полный набор:
   ```bash
   python -m pytest -q                 # юнит-тесты и тесты форматов
   python tests/bench/run.py           # стенд полноты; сравни с прошлым результатом
   python tests/bench/run.py --ner     # то же с NER-слоем
   ```
4. **Живая проверка.** Запусти приложение (`python app.py` или собранный .app), прогони через API или Playwright реальный сценарий: загрузка DOCX → анонимизация → скачивание → деанонимизация → сравнение с оригиналом. Для UI есть `tests/test_ui_playwright.py` - поддерживай его в рабочем состоянии.
5. **Регрессия запрещена.** Процент стенда не может снижаться, ложные срабатывания (столбец FP) и ошибки обратной замены (RT) должны быть 0. Если снизилось - сначала разберись, потом двигайся дальше.
6. **Отчёт.** В конце каждого этапа запиши в `CHANGELOG.md`: что сделано, таблицу стенда «до/после», что проверено руками, что осталось. Владельцу пиши коротко и по-русски.

- `CLAUDE.md` и `CHANGELOG.md` обновлены, если поменялась архитектура.

## 1. Что это за продукт

Локальное приложение для юристов. Задача: отправить документ во внешнюю нейросеть (серверы за рубежом) так, чтобы в ней не оказалось персональных данных, коммерческой и банковской тайны (требования ФЗ-152 и ФЗ «О банках», «О коммерческой тайне»).

Сценарий:
1. Пользователь загружает документы (DOCX, PDF с текстовым слоем, XLSX, TXT, RTF).
2. Приложение находит чувствительные данные и заменяет их **именными плейсхолдерами** (`ООО «[YUL_1]»`, `[FIO_2]`, `[INN_3]`). Структура и форматирование документа сохраняются.
3. Пользователь проверяет результат, при необходимости правит вручную, скачивает.
4. Отправляет документ во внешнюю нейросеть, получает обратно изменённый документ (анализ, редактура, ответ) с теми же плейсхолдерами.
5. Загружает ответ в приложение → **деанонимизация**: плейсхолдеры заменяются исходными значениями.

Всё работает **только на компьютере пользователя**: никаких внешних API, телеметрии, облака. Модели скачиваются один раз и дальше работают офлайн.

**Главная метрика - полнота (recall).** Пропущенное ФИО уходит за рубеж, лишняя маска лишь немного мешает анализу. Поэтому: сначала найти всё, потом фильтровать явный мусор.

**Платформы:** основная - MacBook на Apple Silicon (M4). Windows должна продолжать работать (у владельца есть и Windows-компьютер), но на Windows без видеокарты нейросеть по умолчанию выключена.

Конкретные ошибки:
10. **Телефон `+7 (495) 123-45-67` не ловится вообще** (`anonymizer.py:339-340`): между `+7` и `(495)` шаблон разрешает один символ, а там два.
11. **Женские отчества в косвенных падежах** («Викторовне», «Викторовны», «Викторовной») не ловятся: шаблон `(ович|евич|овна|евна|ична)[а-яё]*` (`:382`, `:395`, `:492`).
12. **Фильтр spaCy отбрасывает почти все фамилии в косвенных падежах** («Кузнецову Игорю», «Петрову», «Ивановым Петром», «Смирновой Анны»): `_SURNAME_ENDING_RE` (`:441`) знает только окончания именительного падежа. Это главная причина, почему spaCy добавляет всего 2%.
13. **spaCy маскирует само «ООО»**: `ООО «Вектор-Плюс»` → `[YUL_2] «[YUL_1]»`, `в ПАО Сбербанк` → `в [YUL_1]`.
14. Типографские кавычки `“ ” „ “ ' '` в ОПФ не поддерживаются: в `_OPF_RE_STRAIGHT` (`:197`) обе «кавычки» - обычные `"`.
15. ИНН без слова «ИНН» перед числом (`7701234567 (ИНН)`, `ИНН № ...`, таблица реквизитов, `идентификационный номер налогоплательщика`) не ловится. Контрольные суммы нигде не проверяются.
16. **Паспорт ломает обратную замену**: заменяется вся фраза `паспорт серии 45 07 № 123456` одним токеном, а восстанавливается `4507 123456` - слова «паспорт серии» и «№» теряются (6 из 6 провалов RT). «Кем выдан» и код подразделения не маскируются.
17. Замена через `str.replace` по всему тексту (`:724`, `:795`, `:822`, `:858`): фамилия «Иванов» заменится и внутри «Ивановский», короткое название - внутри других слов. Нужна замена по позициям (spans) с границами слов.
18. **Регрессия падежей при деанонимизации.** `get_reverse_mappings` (`db.py:250-267`) возвращает `canonical_form`, а для имён от spaCy это именительный падеж (`_normalize_fio`). Как только п. 12 будет исправлен, «Кузнецову» после обратной замены станет «Кузнецов».
19. Одна персона в разных падежах получает **разные токены** (UNIQUE по `original_form`): «Иванов» = FIO_1, «Иванова» = FIO_2. Внешняя нейросеть считает их разными людьми - анализ искажается.
20. Адреса без ключевого слова и адреса с нестандартными сокращениями (`пр-т`, `наб.`, `а/я`) не ловятся; кадастровые номера, госномера, VIN, ОКПО, номера карт, IBAN не ловятся вовсе.

**Форматы файлов**
21. **DOCX: весь конвейер, включая нейросеть, запускается отдельно на каждый абзац** (`handlers.py:212`). В договоре 200-400 абзацев → 200-400 вызовов LLM, каждый с системным промптом заново. Нейросеть видит абзац без контекста документа.
22. DOCX не обрабатывает: сноски, надписи (text box), комментарии и их авторов, свойства файла (`docProps/core.xml` - автор, последний редактор), колонтитулы первой и чётных страниц, вложенные таблицы. Исправления принимаются только в body.
23. XLSX: пропускаются числовые ячейки (`handlers.py:372, 382`) - ИНН и телефоны часто хранятся числом. Не обрабатываются комментарии, имена листов, колонтитулы, свойства.
24. RTF: кириллица в RTF закодирована (`\'e8`, `\uNNNN`), поэтому замена по сырому тексту (`handlers.py:425`) её не находит; файл перезаписывается как UTF-8 и может сломаться.
25. PDF: `page.search_for` не находит значения, разорванные переносом строки; метаданные, закладки и аннотации не чистятся.

**Нейросеть (Ollama)** - почему медленно и «ничего не находит»
26. Сотни мелких вызовов (п. 21).
27. Ответ обрезается: `num_predict: 600` (`llm.py:235`) - длинный JSON не закрывается, `json.loads` падает, ошибка молча проглатывается (`:295-298`), результат пустой.
28. Не используется параметр `format` с JSON-схемой (структурированный вывод Ollama) - модель пишет JSON с ошибками.
29. Найденное отбрасывается, если модель чуть изменила текст (кавычки, пробелы, ё/е): проверка `original not in text` (`:308`).

31. Нейросеть получает текст, где уже стоят токены, но без исходного контекста; промпт требует «найти то, что не замаскировано», и модель часто возвращает пустой список.

## 3. Целевая архитектура детекции

Цель - **ни одного пропуска на стенде и на реальных документах владельца**. Полностью автоматически 100% недостижимо, поэтому архитектура = высокая автоматическая полнота + распространение найденного + проверка утечек + удобная ручная проверка.

```
Документ
  │
  ├─ Извлечение: все текстовые места файла (текст, таблицы, колонтитулы, сноски,
  │  надписи, комментарии, свойства, гиперссылки, имена листов, числовые ячейки)
  │  → список сегментов с адресом в файле
  │
  ├─ Нормализация (с картой смещений) - раздел 0.1 каталога
  │
  ├─ Слой 1. Правила: генераторы кандидатов по форме + контекст + контрольные суммы
  │           → кандидаты с типом и уверенностью
  ├─ Слой 2. NER-модель (локальная, ONNX, CPU) → кандидаты PER / ORG / LOC-ADDRESS
  ├─ Слой 3. LLM (опционально, по железу) → проверка спорных кандидатов
  │           и поиск пропущенного на уровне документа
  │
  ├─ Слияние: объединение кандидатов, разрешение пересечений (длинный и более
  │  уверенный побеждает; ОПФ всегда вырезается из названия)
  │
  ├─ Распространение: каждую найденную сущность ищем по всему документу
  │  во всех формах (падежи, инициалы, регистр, е/ё, кавычки, без ОПФ)
  │  + словарь пользователя из прошлых сессий
  │
  ├─ Замена по позициям (spans), один токен на сущность
  │
  └─ Проверка утечек: повторный прогон всех детекторов по результату +
     поиск исходных значений и их форм в выходном файле и метаданных
     → отчёт «чисто / найдено N подозрительных мест» перед скачиванием
```

### 3.1. Слой 1 - правила
Для каждого типа из каталога - детектор с единым интерфейсом:
```python
class Detector(Protocol):
    type: str                      # 'INN', 'FIO', ...
    def find(self, doc: NormText) -> list[Candidate]: ...

@dataclass
class Candidate:
    start: int; end: int           # позиции в нормализованном тексте
    type: str
    value: str                     # как в тексте
    canonical: str                 # нормальная форма (цифры без разделителей, ФИО в им. п.)
    confidence: float              # 0..1
    source: str                    # 'rule:inn_checksum', 'ner:rubert', 'llm', 'user_dict'
    reasons: list[str]             # для UI: «контрольная сумма», «слово ИНН рядом»
```
- Числовые реквизиты: искать **любую** группу цифр нужной длины с допуском разделителей, проверять контрольную сумму, смотреть контекст (окно ±60 символов, заголовок столбца, соседняя ячейка). Уверенность - по разделу 0.3 каталога.
- ОПФ и названия: **парсер кавычек** со счётчиком вложенности (не регулярка), ОПФ до и после названия, в скобках, во всех падежах, иностранные формы.
- ФИО: шаблоны формы + морфологическая проверка через `pymorphy3` (граммемы `Surn`, `Name`, `Patr`) вместо списков окончаний и стоп-слов.
- Адреса: якоря (индекс, ключевые слова, маркеры улиц и домов) + расширение по словарю частей адреса (каталог, раздел 10).
- Паспорт и документы: маскировать **только значения** (серию, номер, «кем выдан», код подразделения), слова «паспорт серии №» оставлять.
- Проверку контрольных сумм вынести в `core/validators.py` с тестами на известных валидных и невалидных примерах.

### 3.2. Слой 2 - NER-модель
spaCy `ru_core_news_lg` на стенде даёт +2% и ложные срабатывания; его оценка качества завышена (обучен и проверен на «серебряном» корпусе Nerus). Выбери модель **по цифрам стенда**, сравнив минимум:

| Кандидат | Размер | Метки | Заметки |
|---|---|---|---|
| spaCy `ru_core_news_lg` (текущий) | ~500 МБ | PER, ORG, LOC | исправить фильтры (п. 12-13) и сравнить честно |
| Natasha / Slovnet | ~30 МБ | PER, ORG, LOC | CPU, быстро; на factRuEval PER 0.96, ORG 0.83 (по naeval) |
| `redmadrobot-rnd/rubert-base-pii-ner` (есть ONNX: `lockR/rubert-base-pii-ner-onnx`) | ~356 МБ FP16 | 21 тип ПД: ФИО по частям, город, улица, дом, телефон, паспорт, ИНН, СНИЛС... | Apache 2.0; обучен именно на русских ПД; меток ORG нет |
| `LLAIMlegal/ru-legal-ner` | ~30M параметров | PER, ORG, ADDRESS, INN, OGRN, PASSPORT, SNILS, BANK_ACCOUNT, CASE_NUMBER, DATE, POSITION | MIT; ближе всего к юридическим текстам, маленький тест-сет |
| GLiNER multi (`urchade/gliner_multi-v2.1`) | ~800 МБ | любые метки zero-shot | на русских ПД заметно хуже дообученного ruBERT |

Ожидаемый лучший вариант - **объединение** `rubert-base-pii-ner` (имена, адреса) и Slovnet или `ru-legal-ner` (организации). Требования:
- запуск через **ONNX Runtime на CPU** - одинаково работает на Mac и Windows, без torch в сборке;
- длинный текст - скользящим окном (512 токенов, шаг 128);
- модели лежат в папке приложения, `HF_HUB_OFFLINE=1`, никаких загрузок при работе;
- выбранный NER - за интерфейсом `Detector`, чтобы его можно было заменить.
- Лицензии моделей проверь и запиши в `README.md`.

### 3.3. Распространение (главный рычаг полноты)
Для каждой найденной сущности:
- **ФИО:** через `pymorphy3` построить 6 падежей для фамилии, имени, отчества (мужские и женские), формы «Фамилия И.О.», «И.О. Фамилия», «Фамилия И.», только фамилию, ВЕРХНИЙ РЕГИСТР, е/ё, латиницу по ГОСТ транслитерации, если в документе есть латиница. Искать по всему документу с границами слов.
- **Юрлица:** название с кавычками любого вида и без, в верхнем регистре, в падежах (если название из обычных слов), без ОПФ.
- **Реквизиты:** все варианты разделителей одного и того же номера.
- Все формы одной сущности → **один токен** (см. раздел 5).

### 3.4. Проверка утечек перед скачиванием
После сборки выходного файла:
1. Извлечь из него весь текст **и метаданные** тем же экстрактором.
2. Прогнать все детекторы заново.
3. Найти в нём все исходные значения из маппинга и их формы.
4. Показать итог: «Утечек не найдено» или список мест с кнопками «замаскировать» / «это не ПД». Кнопка «Скачать» доступна всегда, но при найденных утечках - с предупреждением.

### 3.5. Экран проверки
Предпросмотр документа с подсветкой: цвет по типу, отдельная метка у мест со средней уверенностью. Клик по подсветке - снять маску, выделение мышью - добавить маску. После правок автоматически пересобирается файл. Это заменяет чтение документа целиком: пользователь просматривает только подсвеченные «сомнительные» места.

## 4. Нейросеть (Ollama): как сделать быстрой и полезной

### 4.1. Роль нейросети
Не «найди всё в сыром тексте» (медленно, много ошибок), а две узкие задачи:
1. **Проверка спорных кандидатов.** Для каждого кандидата со средней уверенностью отправить короткий фрагмент (±200 символов) и спросить: это ПД? какого типа? Короткие запросы с одинаковым системным промптом быстрые (промпт кэшируется).
2. **Поиск пропущенного на уровне документа.** Отправить документ крупными блоками (4-8 тыс. символов, по границам абзацев) **с исходным текстом** и списком уже найденного, попросить только недостающее. Один документ - единицы вызовов, а не сотни.

### 4.2. Технически
- Параметр `format` с JSON-схемой (structured outputs Ollama) + схема в промпте. Никакого ручного разбора markdown.
- `num_ctx` - вычислять под размер блока (например 8192), `num_predict` - с запасом (2048), `temperature: 0`.
- Для моделей Qwen3 и производных - `think: false`.
- `keep_alive` на время пакетной обработки; один неизменный системный промпт.
- Совпадение найденного с текстом - нечёткое (нормализация 0.1 каталога), а не `in text`.
- Любая ошибка разбора - в лог и в UI («блок 3 из 5 не обработан»), а не молча.
- Обработка в фоновой задаче: `POST /api/jobs` → `job_id`, `GET /api/jobs/<id>` (прогресс, этап, найдено), отмена. Прогресс привязан к задаче, а не глобальный.
- Режим «Только LLM» должен реально выключать остальные слои - для честного сравнения на стенде.

### 4.3. Выбор модели и железо
При первом запуске определить железо и замерить скорость (tokens/s коротким тестом), показать владельцу понятный результат:

| Железо | По умолчанию | Модель |
|---|---|---|
| Mac Apple Silicon, 16 ГБ+ | LLM включена | T-lite-it-2.1 от T-Bank (8B, на базе Qwen3, сильный русский; точное имя в каталоге Ollama или GGUF на HuggingFace `t-tech/T-lite-it-2.1` - проверить) или `qwen3:8b` |
| Mac 8 ГБ | LLM включена | `qwen3:4b` |
| Windows/Linux с видеокартой NVIDIA/AMD | LLM включена | как для Mac 16 ГБ |
| Windows/Linux без видеокарты | **LLM выключена**, NER работает | при ручном включении `qwen3:4b` с предупреждением о скорости |

Модели сравнить на стенде и на 3-5 реальных документах владельца (локально, без коммита). Критерий - прирост полноты на единицу времени. На Маке проверить, что `ollama ps` показывает `100% GPU` (иначе модель не помещается в память и уходит на процессор).

NER-слой (ONNX) работает на CPU на любой машине за секунды - это основной слой; нейросеть - дополнительный.

## 5. Обратимость (деанонимизация)

- **Один токен на сущность.** «Иванов», «Иванова», «Иванову П.С.» - всё `[FIO_1]`. Таблица `mappings` хранит сущность (токен, тип, каноническая форма), отдельная таблица `occurrences` - каждое вхождение (файл, место, исходная форма).
- **Обратная замена исходного документа** восстанавливает точную исходную форму каждого вхождения (падеж, регистр).
- **Обратная замена ответа внешней нейросети** (текст новый, мест исходных вхождений нет): по умолчанию подставлять форму, наиболее частую в исходном документе, и **подсвечивать** такие места в отдельном отчёте «проверьте падеж». Опционально - согласование падежа через `pymorphy3` по предлогу/глаголу слева (экспериментальная функция, выключена по умолчанию).
- **Терпимый разбор токенов** в ответе нейросети: `[FIO_1]`, `FIO_1`, `[FIO 1]`, `[FIO-1]`, `[ФИО_1]`, `[fio_1]`, `**[FIO_1]**`, `[FIO_1]у` - одним шаблоном; при двусмысленности (`FIO_1` внутри `FIO_10`) - по границам.
- **Колонка «Базовая форма»** в UI используется только для отображения и ручного переопределения, а не как значение по умолчанию при обратной замене (исправить п. 18).
- Добавить в UI кнопку «Скопировать инструкцию для нейросети»: короткий текст, который пользователь вставляет в чат внешней нейросети, например: «В тексте есть плейсхолдеры в квадратных скобках вида [FIO_1]. Не изменяй, не склоняй и не переводи их, сохраняй как есть».
- Тесты: кругооборот «анонимизация → деанонимизация» по всем файлам стенда и по всем форматам должен давать байт-в-байт тот же текст (для DOCX - тот же текст всех абзацев и то же форматирование runs).

## 6. «Обучение» на данных пользователя

Владелец хочет, чтобы программа учитывала особенности его документов. Дообучение весов модели сейчас не нужно. Реализация:

1. **Личный словарь** (переименовать `known_entities`): значения, которые пользователь добавил или подтвердил вручную, с типом и счётчиком. Применяются в новых сессиях через шаг распространения (со всеми формами). В UI - страница «Мой словарь»: просмотр, поиск, удаление, «очистить всё», экспорт/импорт.
2. **Словарь исключений**: то, что пользователь снял как «не ПД» (например, название банка-посредника), - глобально, тоже с UI.
3. **Выученные контексты**: при ручном добавлении запоминать 1-3 слова слева от значения («цедент», «бенефициар», «номинальный держатель») → эти слова становятся контекстом для слоя правил и подсказкой для нейросети (не больше 20 самых частых, чтобы промпт не рос).
4. Всё это хранится в зашифрованной базе (раздел 7) и включается переключателем «Запоминать мои правки» (по умолчанию включено, с пояснением).
5. Позже, если накопится 30-50 размеченных документов: дообучение NER-модели (ONNX) на этих данных - отдельный этап, не сейчас.

## 7. Безопасность данных

- Данные приложения - в папке пользователя: macOS `~/Library/Application Support/Anonymizer/`, Windows `%APPDATA%\Anonymizer\`. Не рядом с программой.
- База маппинга и словарь - зашифрованы (например SQLCipher или шифрование значений через `cryptography.Fernet`, ключ в Связке ключей macOS / Windows Credential Manager через `keyring`).
- Оригиналы в `uploads/` - удалять автоматически через N дней (настройка, по умолчанию 30) и по кнопке «Удалить сессию».

- Очистка метаданных DOCX/XLSX/PDF (автор, компания, последний редактор, комментарии).
- Сервер: случайный свободный порт, проверка заголовка `Origin`/`Host`, одноразовый токен в URL при запуске. Лучше - нативное окно (раздел 8), тогда браузер не нужен.
- Безопасные имена загружаемых файлов (свой санитайзер с поддержкой кириллицы; `secure_filename` из werkzeug удаляет кириллицу).
