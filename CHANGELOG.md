### Раздел 2. Восстановление (2026-10-03)
- **Мелкий шрифт в Word**: причина найдена — если внешняя программа разрезала токен на run'ы («[» отдельным мелким run'ом), значение вставлялось в первый, крошечный. Теперь значение получает run, где лежит бо́льшая часть токена, со всеми его свойствами (размер, шрифт, жирный). Рабочие файлы владельца, восстановленные из собственных обезличенных копий, этой ошибки не имели — она проявляется на ответах внешних нейросетей.
- **Организации в новом тексте**: в кавычках → название; без кавычек → «название»; без ОПФ рядом (и без слов «компания», «общество»…) → «ООО «название»». ОПФ берётся из документа и хранится у записи (новая колонка `opf`). Настраивается: меню «⋯» → «Настройки восстановления».
- **Падеж**: склоняются только ФИО (организации, номера, адреса, даты — никогда). Правила (`core/cases.py`): предлоги у/для/от/без/к/по/с/между/о/при, обороты «в лице», «от имени», «со стороны», глаголы «передать/направить/сообщить…» (дательный) и «уведомить/просить/обязать…» (винительный), подлежащее в начале фразы. Фамилии и отчества — по окончаниям (pymorphy3 не знает редкие фамилии), имена — pymorphy3. Остальные места — один короткий запрос к нейросети (ответ `{"1": "…"}`), принимается только форма того же ФИО.
- **Подсветка**: места с подобранным падежом — жёлтая заливка Word в скачанном файле (галочка в настройках, по умолчанию включена; значение — отдельный run с теми же свойствами) и жёлтый в просмотре.
- **Просмотр восстановленного файла**: красный блок «подозрительные места» убран; все вставленные значения подсвечены — зелёный (точно), жёлтый (падеж подобран), красный (токен не найден); справа — список с переходом к месту (повторный щелчок — следующее вхождение), текст выделяется; сверху строка «Восстановлено 42 значения: 39 точно, 3 с подбором падежа, 0 не найдено». В строке файла: «В N местах падеж имени подобран автоматически — они подсвечены жёлтым».
- **Чужой текст**: генератор `tests/fixtures/ai_rewrite.py` (резюме, письмо, список, таблица рисков, вопросы; токены в разных падежных позициях, испорченные `[FIO 1]`, `FIO_1`, `**[YUL_2]**`; размеры 8-16 pt; эталон) и живая проверка `scripts/e2e_private.py --rewrite` (локальная модель переписывает документ в служебную записку).
- Падеж по смыслу: однородные имена («от [FIO_1] и [FIO_2]») — в одном падеже; приложение к одушевлённому слову («нотариусом», «предпринимателем», «директор») — в его падеже; после неодушевлённого («семьей», «долю») — родительный, но «договора [FIO] обязуется» — именительный. Из ответа нейросети берётся только падеж, форму строят правила (нейросеть однажды вернула «Ветров Германом…»). «Гуревич» → «Гуревичем», не «Гуревичом».
- Разбор ФИО (`Person.parse`, влияет и на объединение записей): фамилия, которую pymorphy3 принимает за имя («Тарханов» как мн. ч. «Тархан», незнакомая «-ин» как угаданное имя), теперь фамилия, если рядом словарное имя или инициалы. Пример из личного набора: полное ФИО и «Фамилия И.О.» одного человека получали два токена — теперь один.

Проверено: pytest 264; стенд 245 — 99%, FP 0, RT 0; личный прогон «Быстро» 24 файла — 0 ошибок, дублей 0; живая проверка «записка» (qwen3.5:9b, 12 документов, 30-60 с на записку): токенов не осталось, 27 мест с подбором падежа — 25 верно (ошибки: однородность с обычным словом «Ассоциацию … и [ФИО]»; бессмысленная фраза самой модели); вставка значений, подсветка, итог и окно настроек проверены в браузере (Playwright, снимок экрана).

### Раздел 1. Данные: дубли и составные номера (2026-10-03)
- **Аудит рабочей базы** (`scripts/audit_db.py`, только чтение, значения — только на экран): 13 сессий, 319 записей. По правилам до исправления: ЮЛ — 1 группа дублей (форма «ОсОО» и незакрытая кавычка внутри значения); по новым правилам найдено ещё 5 групп адресов (один дом: «р-н»/«район», «пос.»/«пгт», «р-н Х»/«Х р-н», с запятой и без).
- **Правила объединения по типу**: номера и реквизиты — только при совпадении цифр (и букв серии), никогда по похожести; ФИО — леммы + совместимые инициалы, группа объединяется, только если все формы попарно совместимы; организации — без ОПФ, кавычек, регистра, ё, пробелов (или те же леммы слов); адреса — сокращения, тип населённого пункта, район, пунктуация, переносы, порядок слов до дома; дом, корпус, квартира, помещение — по порядку (разные дома/корпуса/помещения — разные записи).
- **Проверка базы в конце обработки** (этап `consolidate`): одна сущность под несколькими токенами объединяется в меньший, старый токен остаётся псевдонимом (старые файлы восстанавливаются).
- **«Предложить человеку»** (для раздела «Проверка дублей»): однофамильцы с другими инициалами, организации с расхождением 1 символ на 8, адрес = другой + помещение/квартира, опечатка при тех же номерах; номера не предлагаются; «Это разные» запоминается (таблица `distinct_pairs`) и не предлагается/не объединяется снова.
- **Ручное добавление и правка**: «Такое значение уже есть: [ADR_1] … — Объединить с ним / Всё равно добавить отдельно / Отмена».
- **Номер записи ЕГРН** — отдельный тип `EGRN`, маскируется целиком: новый формат (кадастровый номер + «-NN/NNN/ГГГГ-N») и старый («NN-NN/NN-NNN/ГГГГ-NNNN»), с пробелом у дефиса, без слова-подсказки. Номера свободной формы (кадастр, рег. номера, лицензии) продлеваются через «-», «/», «.», «:» до конца идентификатора; номера с контрольной суммой (ИНН/КПП подряд) не склеиваются.
- Стенд строже: утечкой считается и **остаток** номера рядом с токеном («[CAD_3]- 71/022/2020-18»); проверено — без нового детектора стенд падает (Недвиж. 66%).

Проверено: pytest 215 (новые: дубли по типам, предупреждение в API и в браузере, составные номера); стенд 245 вариантов — 99% без NER и с NER (было 241 — 99%), FP 0, RT 0; личный прогон 24 файла — 0 ошибок, дублей в базе после прогона 0, остатков номеров после токенов 0.

- **Проверка утечек** после сборки каждого файла: готовый файл читается заново, подозрительные места показываются в интерфейсе.
- **Один токен на сущность** (этап 5): все падежи, инициалы, заглавные, фамилия отдельно — один `[FIO_N]`; названия организаций в любом регистре и падеже — один `[YUL_N]`. Для каждого файла запоминается форма в каждом месте — деанонимизация возвращает точный падеж. Для нового текста нейросети подставляется основная форма.
- Распространение: фамилия найденного лица в любом месте текста маскируется тем же токеном.

- **Приложение для Mac**: нативное окно (pywebview) с иконкой, `build_macos.sh` → `Anonymizer.app` + `Anonymizer.dmg`, один `Anonymizer.spec` для Mac и Windows. Данные — в `~/Library/Application Support/Anonymizer`, оригиналы удаляются через 30 дней.

- RTF: восстановленная кириллица корректна и в файлах с `\\uc0`.
- Таблица замен показывает одну строку на метку со всеми формами («Иванов Пётр Сергеевич · Иванову П.С. · Иванов»).
